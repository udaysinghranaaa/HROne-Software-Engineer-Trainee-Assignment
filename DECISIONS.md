# DECISIONS.md

1. **Indexes.** Seven startup indexes enforce employee and employee/day uniqueness and support department/code, date/code, latest-punch, joined/department and department/joined queries. Saved 100k plans used these indexes without collection scans in tested shapes. Additional indexes increase storage and write costs; I would require measured query benefits before adding one.
2. **Punch-in race.** Both requests insert; the unique employee/day index admits one. DuplicateKeyError becomes 409; the winner returns 201. Punch-out and corrections compare stored snapshots. Corrections atomically set changed fields and push one history entry, preventing lost audits. No process lock is needed.
3. **Ties.** MongoDB competition rank uses late totals alone. Equal totals share rank, leaving gaps. Department filtering precedes ranking; rank <= limit retains cutoff ties. Employee code stabilizes order.
4. **Headcount.** Eligible employees anchor the summary; grouped attendance lookups default missing statistics to zero. Zero-log employees count. Work-hour averages are record-weighted. UTC BSON instants serialize as milliseconds; IST dates and decimal half-up preserve the business rules.
5. **100x data.** I would measure nested plans before evaluating department-first aggregation or incremental daily summaries. Trend's attendance lookup dominates saved timing. Summaries trade repeated scans for correction-invalidation complexity. Small-sample p95 and RSS snapshots are not production guarantees.
